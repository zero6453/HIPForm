## 已确认并修复的问题

| 级别 | 问题与影响 | 处理 |
| --- | --- | --- |
| P2 | 本地服务只检查 Host；携带外站 Origin 的 multipart 上传仍返回 201 并落盘 | 写请求检查同源，外站及 null Origin 返回 403；保留 Swagger 和普通 Python 客户端调用 |
| P2 | CLI 将来源 JSON 当作字典；`[]` 或 `{"capsule": []}` 导致未处理的 AttributeError | HTTP 与几何模块共用来源校验，网格生成前拒绝；CLI 返回 2 并保留失败报告 |
| P3 | 比较误差容限使用了未参与比较的顶点和未使用的区域公差；极端输入可让超差误判通过 | 舍入容限只依据实际比较表面的坐标，保留原有输出结构 |

第三项的复现使用极端值：11 mm 偏差、10 mm 公差，在未使用的角度公差设为 `1e15` 时曾被判为通过。
正常尺寸用例之外增加该测试，用于保证不相关输入不能改变公差结论。

## 结构与维护性

- `api.py` 负责 HTTP 适配，上传落盘移入存储层；同步文件操作由 FastAPI 的线程池执行。
- `inputs.py` 统一 STEP 限大小复制、流式 SHA-256 和可选来源文件校验。上传与本地快照共用该实现。
- `jobs.py` 提供统一的结果文件可见性规则；任务查询使用同一份状态记录，消除按文件重复读取 `job.json`。
- 失败任务仍不能下载中间预测模型，原有防覆盖、快照、超时和进程恢复机制均有回归覆盖。
- 报告中的可见性计算改为命名函数，清理确认未使用的导入，保留测试的可选依赖检查。

本次没有增加生产依赖。新增输入模块承载已存在的重复逻辑，HTTP 路由从 267 行缩至 242 行。
评价依据是职责和校验规则更集中；测试和修复必要的校验会增加总行数，因此不以总行数下降作为目标。

## 流程与验证记录

1. `coding-standards`：读取已有约定、全量代码清单和基线测试。
2. `codebase-design`：确定 HTTP、存储、STEP 输入、仿真和报告的职责；保留公开调用契约。
3. `tdd`：同源防护、来源结构、公差边界均先观察失败测试，再实现修复；逐项验证。
4. `code-simplification`：在已有行为测试保护下集中重复逻辑，每次调整后运行相关测试。
5. `code-review-and-quality`：独立检查几何/数值与输出模块，再复核最终输入/API 改动。

`karpathy-guidelines` 贯穿上述步骤。历史代码本身不能证明过去每次开发都采用 TDD；此处记录的是本次执行过程。

## 保留的边界

审查结论适用于现有小应变、未标定近似模型。计算完成仍不等同于制造验收。
当前输出预测 STL/VTU，公差基准仍为初始型腔；独立目标 STEP 比较、解析 STEP 重建、复杂弯管残余空间识别
属于后续功能。本地串行任务服务的历史列表仍一次返回全部任务，大规模部署需单独设计分页和资源管理。
